# Online Boutique

This repo contains a modified version of Service Weaver's [`Online
Boutique`][boutique] demo application, for the purpose of benchmarking.

[boutique]: https://github.com/ServiceWeaver/onlineboutique

to see some basic usage, run `make` in the root of the directory.

## Some dependencies:
- [go](https://go.dev/doc/install)
- [weaver](https://github.com/ServiceWeaver/weaver)
- [weaver-kube](https://github.com/ServiceWeaver/weaver-kube)
- [minikube](https://minikube.sigs.k8s.io/docs/start/?arch=%2Flinux%2Fx86-64%2Fstable%2Fbinary+download#what-youll-need)
- [kubectl](https://kubernetes.io/docs/tasks/tools/install-kubectl-linux/#install-kubectl-binary-with-curl-on-linux)

## Additional Setup  
- Change the `DOCKER` variable in `.env` to point to a docker account that you can push / pull images to and from. Nothing will work if you don't do this.
- Set the other variables in `.env` to fit your needs. See below to see how to use `DEFAULT.cfg`

### VTune Profiling
- First, ensure that vtune is set up and installed.  
  - The scripts assume that vtune is installed in `/opt/intel/oneapi/vtune/latest`,
  - And that `/opt/intel/oneapi/vtune/vtune_results` can be used to write results into.
- Second, ensure `LOCUST_SHAPE` is set to `dummyload` in `.env`.
- Then, should be as simple as doing the following:

```bash
./utils/vtune_cfgs.py
sudo ./utils/vtune.sh $USER
```
Note: Currently, sudo is required because the kubernetes pods being profiled run as root.  
I am not sure how to fix this, but for now it is a temporary fix.

### Benchmarking
- It is recommended to set `LOCUST_SHAPE` to `rampload` in `.env`
- If you only wish to benchmark one environment, simply set the values in `DEFAULT.cfg` that fit your need, and then run `./make.sh bench`.
- If you want to run multiple benchmarks at once: 
  - either define multiple `*.cfg` files in the `cfgs/` dir, or generate them using `utils/generate_cfg.py`.
  - Then, run `make bench_all` and wait.
- Regardless, the output should appear in the benchmark dir.

## Navigating this project

- `benchmark/`: benchmark results are put into here. 
  - Rest of the dir used to be used to analyze benchmark results, 
  - but those files are not up to date.
- `cfgs/`: Used for vtune profiling or running `make bench_all`.
  - Intended to contain .cfg files generated by scripts in `utils/`, but can be added to manually as well.
- `make_scripts/`: scripts that rely on env variables set by the makefile. 
  - Calling these scripts directly is unlikely to be useful.
- `release/`: contains the following:
  - `release/generated/`: deployment yaml files used by kubernetes 
  - `release/base/`: files used to generate the yamls in `release/generated/`
  - `release/base/colocation/`: yaml files that specify how OB components should be fused.
- `scripts/`: scripts that can be called directly, and do one of the following:
  - Have a frontend command in the makefile, do things like disabling hyperthreading or starting minikube.
  - Can be called while a kubernetes deployment is live to print out some information.
  - Note that some of these scripts may not be up to date.
- `src/`: Contains the actual OB code. 
  - `src/loadgenerator/`: The code used by the load generator, Locust.
  - This dir is not tied to the rest of the src dirs.
- `utils/`: Contains more experimental scripts, mostly to generate cfgs or to run vtune.
